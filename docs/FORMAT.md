# 自实现容器与压缩格式

实现：core/container.hpp。没有调用压缩库或系统压缩程序。所有整数为无符号小端。

## BKNARC2 单文件容器

头部依次为 ASCII `BKNARC2` 加换行（8 字节）、条目数 uint32、原始文件总字节数 uint64。每项为类型 uint8（0 目录，1 文件）、UTF-8 相对路径长度 uint32、路径字节、文件长度 uint64；文件项后接若干数据块。整个容器末尾附 uint32 CRC32，覆盖此前的头部、路径和数据。

每个块依次为原始长度 uint32、存储长度 uint32、模式 uint8、原始数据 CRC32 uint32、有效载荷。原始块不超过 64 KiB；模式 0 为原样，模式 1 为下述 RLE。文件长度决定块读取终点。快照容器包含 manifest.bkn 与 data 目录；普通目录快照格式仍可读取。

## RLE 编解码

控制字节低 7 位加 1 得到长度（1–128）；最高位为 1 时，后续一个字节重复该长度；最高位为 0 时，后续该长度字节为原样文字。编码器对连续至少 3 个相同字节生成游程，其余生成文字段。每块编码长度不小于原长度时回退为原样块。

独立压缩文件头为 ASCII `BNRLE1` 加换行（7 字节）和 uint64 原始长度，其后使用相同分块编码。因此压缩和容器可以独立调用与测试。

## 校验与边界

解码前验证整体容器 CRC，解码时验证块 CRC、合法模式、长度、条目计数、重复路径、相对路径越界、平台非法路径、父目录关系与多余尾部数据。默认总输出上限 8 GiB、条目上限 200,000。块缓冲限制为 64 KiB 量级，避免按不可信头部一次分配整个文件大小。

写入临时输出，完成校验后提交。备份取消与提交通过共享 decision 目录仲裁，取消先到则禁止发布；提交先到则拒绝取消。CRC32 是损坏检测，不能替代密码认证。校验容器时会解包到临时目录，需要额外磁盘空间。
